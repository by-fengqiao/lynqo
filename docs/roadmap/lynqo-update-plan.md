# LYNQO 更新计划

这套计划按“先稳定连接，再提高传输可靠性，最后扩展桌面体验和社区运营”的顺序安排。当前最重要的不是继续增加页面，而是让用户能够顺利连接设备，并且可靠地完成大文件传输。

## 第一阶段：连接和授权稳定性

目标：让新用户能够顺利完成第一次连接。

### 1. 连接诊断

- 显示当前电脑局域网 IP、端口和网络名称；
- 检查服务是否监听在局域网地址；
- 检测防火墙、网络隔离和端口不可达问题；
- 提供“手机无法连接”的排查入口；
- 二维码下方显示可复制的完整地址；
- 区分 `localhost`、局域网地址和无效地址。

验收标准：用户遇到连接失败时，可以看到具体原因，而不是只看到“连接失败”。

### 2. 设备身份优化

- 自动读取设备型号和平台信息；
- 支持用户修改设备名称；
- 为设备生成稳定 ID；
- 页面刷新后复用原设备会话；
- 合并重复的 `Android Device`；
- 显示最后连接时间和 IP 地址。

验收标准：同一部手机刷新或重新连接后，不再产生多个重复设备。

### 3. 授权状态同步

- “仅本次允许”和“信任设备”使用不同提示；
- 授权、拒绝和撤销操作实时同步到手机；
- 撤销授权后手机立即失效；
- 增加“撤销所有设备”；
- 授权请求显示设备名、平台、IP 和请求时间。

验收标准：电脑端点击授权或撤销后，手机端无需刷新即可更新。

## 第二阶段：传输可靠性

目标：解决大文件失败、速度不稳定和任务状态不准确的问题。

### 4. 断点续传和失败恢复

- 网络短暂中断后自动重连；
- 失败任务支持继续传输；
- 暂停后继续，而不是重新开始；
- 失败任务显示明确原因；
- 对 HTTP 409、连接断开、权限拒绝分别处理；
- 多文件连续上传时保持队列顺序。

验收标准：1 GB 以上文件中断后可以恢复，不能出现任务重复或状态丢失。

### 5. 实时进度优化

- 速度采用平滑计算，避免一闪一闪；
- 剩余时间使用最近一段时间的平均速度计算；
- 手机端和电脑端使用同一套任务状态；
- 传输完成后立即进入已完成列表；
- 页面刷新不会丢失正在传输的任务；
- 电脑端无需手动刷新即可看到手机端任务。

验收标准：手机和电脑显示的文件名、进度、速度、状态一致。

### 6. 完整性校验

- SHA-256 计算放入后台任务；
- 大文件校验过程中显示真实进度；
- 传输完成后自动计算校验值；
- 校验失败时提供重新传输按钮；
- 支持复制短校验摘要，同时保留完整 SHA-256；
- 记录发送端和接收端的校验结果。

验收标准：校验过程不再永久停留在“计算中”，并且不会阻塞传输中心。

## 第三阶段：传输中心完善

目标：把传输中心做成 LYNQO 的核心页面。

### 7. 统一任务管理

- 合并传输中、已完成、失败和待处理任务；
- 增加筛选：全部、进行中、已完成、失败；
- 支持按设备、时间和文件名搜索；
- 支持批量重试和批量删除；
- 保留失败原因和操作记录；
- 支持打开文件所在目录。

### 8. 桌面端实时通知

- 传输开始时通知；
- 传输完成时通知；
- 传输失败时通知；
- 系统托盘显示当前任务数量；
- 托盘菜单显示“正在传输”“已完成”“失败”；
- 点击通知可以直接打开对应任务。

## 第四阶段：桌面端设置和系统集成

目标：让应用适合长期运行。

### 9. 系统托盘设置

- 关闭窗口时退出；
- 关闭窗口时最小化到托盘；
- 开机自动启动；
- 启动后自动启动局域网服务；
- 托盘图标显示运行状态；
- 托盘菜单支持启动、停止服务；
- “右上角运行中”和“托盘运行中”统一为同一个状态源。

### 10. 跨平台体验

- Windows 防火墙提示优化；
- macOS 网络权限说明；
- Linux AppImage 和 deb 安装说明；
- macOS Intel 与 Apple Silicon 安装包分别标注；
- 统一各平台设备名称和图标；
- 检查不同浏览器的移动端兼容性。

## 第五阶段：安全和隐私

目标：让用户知道文件如何传输、谁可以接入。

### 11. 权限最小化

- 默认只开放文件传输能力；
- 不提供无关的文件系统权限；
- 信任设备可以单独撤销；
- 显示当前授权设备；
- 增加授权过期策略；
- 记录最近的授权和撤销操作。

### 12. 隐私说明

- 明确说明文件是否经过云端；
- 明确说明局域网和公网的区别；
- 增加网络不可信时的提醒；
- 在首次启动协议中说明应用边界；
- 在帮助中心增加“为什么手机连不上电脑”；
- 在帮助中心增加“文件传输是否经过服务器”。

## 第六阶段：社区和产品运营

目标：从“有代码”变成“有用户、有反馈”。

### 13. GitHub 项目完善

- README 首屏放安装包和演示图；
- 增加 30 秒扫码传输 GIF；
- 增加中英文快速开始；
- 增加常见问题页面；
- 增加故障报告模板；
- 每个版本记录修复了哪些真实问题；
- 标注已知限制，不夸大功能。

### 14. 建立测试反馈机制

建议收集这些数据：

- 首次连接成功率；
- 从扫码到授权完成所需时间；
- 设备发现失败次数；
- 1 GB 以上文件成功率；
- 失败后恢复成功率；
- 不同手机型号、浏览器和路由器的兼容性；
- Windows、macOS、Linux 各平台的问题分布。

### 15. 社区发布节奏

每个版本可以固定包含：

- 本版本解决的问题；
- 新增的功能；
- 已知限制；
- 测试环境；
- 安装包和校验值；
- 下一版本计划；
- 如何提交问题。

社区内容可以围绕实际问题发布：

- 手机和电脑同一个 Wi-Fi，为什么还是连不上？
- 为什么传大文件时需要断点续传？
- 局域网传文件是否真的不经过云端？
- 浏览器传文件和原生应用有什么区别？

## 建议的版本拆分

### 下一版本：连接稳定性版本

重点完成：

- 连接诊断；
- 设备名称和设备 ID；
- 重复设备合并；
- 授权实时同步；
- 手机和电脑状态统一；
- 修复 404、旧数据残留和刷新重复授权问题。

### 再下一版本：可靠传输版本

重点完成：

- 断点续传；
- 自动重试；
- 多文件连续上传；
- 稳定速度和剩余时间；
- SHA-256 后台计算；
- 失败任务批量重试。

### 后续版本：桌面体验版本

重点完成：

- 托盘设置；
- 开机自启；
- 关闭行为；
- 系统通知；
- 跨平台权限提示；
- 设备和传输历史管理。

### 稳定版之后：社区增长版本

重点完成：

- 完整 README；
- 演示 GIF；
- 常见问题；
- 用户反馈模板；
- 兼容性测试表；
- 双语 Release；
- 社区案例和用户反馈展示。

## 开发顺序

建议按照下面的顺序推进：

> 连接成功率 → 设备身份 → 传输可靠性 → 传输中心 → 系统集成 → 社区增长

目前不建议优先开发公网中转、复杂账号系统或过多社交功能。LYNQO 最有价值的差异，仍然是“电脑端可控、手机端免安装、局域网优先、权限明确、传输过程透明”。
